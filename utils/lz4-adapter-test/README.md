# LZ4 adapter regression tests

`make test` builds the unchanged upstream library and production KOS decoder
with instrumented malloc/calloc/free. It also includes the production service
loop against a small scheduler/IRQ double. The common host-suite runner finds
this Makefile automatically.

Coverage:

- State creation prepares both upstream scratch buffers without consuming
  frame payload or writing the destination.
- Every creation allocation can fail with ENOMEM, with no leaked allocations
  and no destination modification.
- Small-budget and multi-block decoding perform no further allocations;
  linked and independent frames preserve byte budgets, CRCs, and output guards.
- Dictionary-backed linked and independent multi-block frames survive setup
  priming (upstream must receive the dictionary before leaving its init stage).
- One-step successful, failed, and cancelled jobs yield between jobs; a
  callback can refill the queue without bypassing a yield.
- Queue-full handling, callback-time destruction protection, and executor
  stop after terminal/partial steps leave all jobs finalized and no leaks.
- Cancellation at the first partial-decode yield keeps a running job busy until
  service finalization. Its callback runs once with CANCELLED/ECANCELED and the
  unchanged seven-byte output prefix; destruction remains busy inside that
  callback. The owner destroys the job and frees output at the next yield,
  before service continuation, with no later access or post-setup allocation.
  The still-running service itself remains busy until its entry returns.
- Header requirements match actual upstream scratch requests for all four
  advertised block sizes, in both independent and linked modes.
- One-byte-below limits reject before scratch allocation; exact limits pass.
  The Compact profile rejects linked/oversized blocks, while NULL/zero caps
  and legacy entry points retain general frame compatibility.
- Header query failures leave results untouched, distinguish ENOMEM from
  malformed headers, and leak nothing. State and job rejection leave output
  untouched even when the first scratch allocation is configured to fail.
- Every truncation point in generated compressed and uncompressed frames,
  independent and linked modes, and all four block/content checksum flag
  combinations fails without successful completion. Explicitly flushed
  three-block frames cover inter-block boundaries as well as the footer.
- Trailing bytes, concatenated frames, skippable frames, incorrect destination,
  section and declared content lengths, oversized blocks, and separately damaged
  header, payload, block, content and section checksums are rejected.
- Each new frame case runs synchronously and with one-byte, seven-byte and
  larger-than-output step budgets. Successful bytes agree, failed states remain
  failed, progress stays bounded, setup leaves output untouched, and stepping
  makes no allocator calls. Failed partial output is not assumed to agree
  across budgets or to be usable.
- Truncated sources use allocations ending exactly at the advertised input
  end. Output has prefix/suffix canaries, with its suffix also poisoned under
  ASan. The valid-frame sweep independently varies both buffer offsets 0-31;
  zero-length Compact sections are rejected and one- through eight-byte
  outputs exercise small tails.
- Dictionary ID checks are separate from content checks. A fixture first
  proves that it references dictionary bytes. With no frame content checksum,
  the vendor decoder can accept altered dictionary bytes despite a valid block
  checksum; the adapter's original section CRC rejects the resulting changed
  output. A matching replacement section CRC can admit that output, while a
  frame content checksum still rejects it. Altering unused dictionary bytes
  need not cause failure. IDs and checksums are not cryptographic authenticity.

The new corpus is in `frame-cases.h`, included by `test.c`. It uses deterministic
generated bytes and the vendored compressor, not external assets. The corrupted
cases are focused regressions, not a fuzzer or an exhaustive LZ4 format proof.
Post-setup allocation assertions cover the stepped adapter path; synchronous
calls share that production step implementation but perform their own setup.

The scheduler double observes calls to yield; it does not emulate real fiber
context switching, preemptive races, interrupt submission, or hardware latency.
The Dreamcast `pvr/chunk_asset` example exercises the real service runtime.

Examples:

```sh
make clean test CC=clang
make clean test CC=gcc-14 HOST_CSTD=c23 HOST_PEDANTIC=-pedantic
make clean test CC=clang HOST_CSTD=c2x HOST_PEDANTIC=-pedantic HOST_LZ4_WARNINGS=-Wno-constant-logical-operand
make clean test CC=clang CFLAGS='-O1 -g -std=gnu17 -Wall -Wextra -Werror -fsanitize=address,undefined -fno-omit-frame-pointer'
```

Do not run different compiler lanes concurrently in this directory.
The strict Clang lane uses the host runner's existing suppression for constant
logical operands in unchanged upstream LZ4; it does not require vendor edits.
