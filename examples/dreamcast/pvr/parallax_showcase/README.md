# Neon harbor — 2D showcase

`make` builds `parallax-showcase.elf`; `make run` uses the configured loader.
All artwork is generated by the example. No external assets or ports are needed.

Build with assertions enabled; `NDEBUG` is rejected because assertions check
rendering calls as well as their results.

Three wrapping tile maps use different scroll rates, scales, colors and depths.
Two independently offset cell streams animate ship atlas frames. A fixed pool
feeds fading, additive particle billboards behind the main ship. The foreground
dock can occlude objects through the normal PVR depth test. No per-frame heap
allocation or service executor is involved; the application owns the clock,
maps, cell state, pool, materials, scene and texture lifetime.

- A: toggle parallax versus a common screen-space scroll rate.
- B: stop/resume new exhaust particles; existing particles expire normally.
- X: toggle atlas animation; motion continues.
- Y: pause/resume scene simulation.
- Start: exit.

The simulation advances by an explicit 1/60 second per rendered frame. This is
a deterministic demonstration, not wall-clock pacing or an FPS benchmark.
`make smoke` builds `parallax-smoke.elf`: 180 frames exercise parallax on/off
and animation on/off, then check nonempty output and a clean PVR fault record.
This does not automate controller input or verify framebuffer pixels, and it
does not substitute for physical Dreamcast validation.
